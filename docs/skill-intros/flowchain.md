# flowchain

flowdeck 界面上那条四格流程链不是画给你看的装饰：每一格背后都挂着**真正在跑的技能**，每一格对应 `.scratch/` 里的一个产物。这篇是那张链的**导读**——按格子从左到右走一遍，说清每格在解决什么、挂着哪些技能、各自管哪一段。想知道某个技能的完整介绍，顺着链接进那一篇即可；这里只给「为什么是它」的判词。

技能名单与流程链的阶段定义同源：grill 格挂 grilling 与 wayfinder，spec 格挂 to-spec，tickets 格挂 to-tickets，implement 格挂 implement。

## 一、grill 拷问：想法 → map.md

这格回答「**我要做什么、做到什么算完**」。产物是 `map.md`——终点、迷雾（还没定的决策）、已定与出界的部分。链格上「推定 · 无 map」的标注也在这格出现：拷问过程不落盘时，下游文件本身就是走过的证据。

- [grilling](grilling.md) — **访谈的地基**。把方案映射成设计树，按轮推进、每轮问全前沿、附推荐答案，前沿清空才算达成共识。查事实是代理的活，做决策是你的活。绝大部分想法在这一步就够用了。

- [wayfinder](wayfinder.md) — **同一场访谈的大工程版本**。当工程大到装不进一个会话、前路还裹着雾时，把访谈产物画成一张决策地图，一次只解一票，解到路清为止。它和 grilling 挂在同一格，因为它们解的是同一个问题：一个想法够不够清楚。

## 二、spec 规格：理解 → spec.md

这格回答「**理解收敛成什么**」。拷问完你脑子里清楚、文档上未必清楚；这格把对话综合成一份能对着干活的规格，产物是 `spec.md`。这一格不访谈、只综合——问出来的答案已经足够，缺的是把它们排成序。

- [to-spec](to-spec.md) — **把聊透的对话收成一份规格**。不重新问你一遍，只把你已经说清楚的整理、去重、排优先级，写成可执行的文档。下一格拆票全靠它。

## 三、tickets 拆票：规格 → 票 issues/

这格回答「**谁先做什么**」。规格再清楚也太大，Agent 一次装不下。产物是 `issues/` 下的一叠票，每张票是一个能独立落地的竖切片，并各自声明阻塞边。

- [to-tickets](to-tickets.md) — **把计划拆成一张张曳光弹**。每张票声明它依赖哪张票，于是「现在能干什么」有确定答案——依赖全结且未被认领的票就是前沿票。界面上的阻塞计数与前沿清单都读这份依赖边。

## 四、implement 实现：逐票实现 → 全部关闭

这格回答「**怎么把它变成代码**」。产物不是文件而是状态：这一格完成的标准是票全部关闭。点链格复制的是这一格的实现指引，粘给任意 Agent 就能接着干。

- [implement](implement.md) — **按票实现**。把规格或一组票变成代码：内部跑 TDD 推进、勤跑类型检查，收尾时全量测试加双轴评审，然后提交当前分支。

## 四格跑完之后

四格全绿即**完工**。flowdeck 界面会把这个 effort 收进切换条的「✓ 完工 (n)」折叠入口（收起来只是显示偏好，`.scratch/` 一个字节不动），但产物都还在 `.scratch/` 里随时可查。想了解整包 35 个技能的分工全景，从 [总览](README.md) 进。
