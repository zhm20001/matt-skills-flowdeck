# 指引词不预设工程习惯；改写权归使用者

flowdeck 的默认指引词不写死任何工程纪律——不要求开分支、不要求开 worktree、不提并行协作。指引词出厂是逐字固定的**内置段**；使用者可在设置弹窗的「指引词」分区里为五面（grill / spec / tickets / implement / 票行）各写一份**自定义段**，非空即整段取代内置段，为空回落内置段，中英各判各的。

**Why**：工程习惯（开分支还是开 worktree、一个 Agent 还是多个并行）是使用者自己的事，工具不该替所有用户做这个决定。上一轮 `branch-discipline` effort 把「开分支、合回 main」织进三处指引词并逐字钉进 verify，代价是：一条个人习惯被固化成所有用户的出厂默认；等并行协作的需求冒出来时，补救又依赖一个多数用户没装的 `using-git-worktrees` 技能——**真正缺的不是措辞，是改写权**。产品因此从「规定怎么做」转向「由你说了算」。

## Considered Options

- **把 worktree 纪律写进默认词**（本次议题的起点）：一次做完，但等于把一个人的习惯强加给所有开源使用者。且 flowdeck 对 worktree 无判据无感知——它背书了一套 git 运维流程，却看不见这套流程的后果（worktree 忘了 `prune` 会在仓库里留一堆陈旧目录）。
- **前置附加**（使用者写一段文字拼在内置段之前，内置段的票数/路径/阻塞提示仍由内置段提供）：**以单行「前缀」的形式复活**（`guides-prefix` effort）。此条一度作废，理由是「实际无人填写——只写 implement 一面的人直接改写全文更省事」；**该理由于 2026-09 被使用事实推翻**：起事者正是"只写 implement 与票行两面"的那类使用者，而"改写全文"对他是三件难事叠加——设置面板不显示默认文案，无从抄起；内置段的票数与路径逐 effort 变化，抄下来只对当前 effort 成立；自定义段全局而内置段不全局，这个差别在界面上无处说明。复活的形态比当初设想窄得多：一个平级字段、一面一行、中英不分列、不是子系统。术语也从「纪律段」改为**前缀**——那个名字暗示"工程纪律"，而实际需求是粘给 Agent 的一句技能调用；改名之后这个概念不再只关于纪律，装什么由使用者自己填。
- **模板占位符**（让用户在自定义段里写 `{{tickets}}` 之类）：已否。仅票行那面例外保留 `{key}` `{path}` `{title}` 三个固定槽——它是最细粒度的一面，全文覆盖成静态文字会产出「请实现这张票」而无票号、无路径、无标题。四个阶段面同样以 effort 为身份，只是粗一级，所以那条理由并不只属于票行；阶段面至今无槽是**当前实现的事实**，不是从这条理由推出来的结论。

## Consequences

未来读者会问「为什么默认指引词一个字 git 都不提」——不要为「更完整」把纪律织回默认词。要加一句每次都要说的固定话，写进**前缀**（逐面一行，复制那一刻贴在最前）；要重写整段话，写进自定义段。两者都住在 `config.json` 里、都是逐使用者的，都不流进出厂文案——这正是本决策要的形状。同理，verify 不得改回逐字钉原文：那条路每次改措辞都要全文对照，而 README 里那份复制品已经这样漂过一次（英文「起步约定第 4 步」与 `index.html` 的权威源不一致，直到本次一并收敛成指针）。

机器面在守这条决策：`verify-standalone.mjs` 的指引词组**不查逐字原文**，查的是规则。四条规则里，**前两条随本次回退落地**（零 git 指令 / 不点名 Matt 包外技能），**后两条（出厂自定义段为空 / 非空即取代）要等自定义段本身落地才成立**——那两件是票 02/03 的事；此处记的是这条决策打算守住什么，不是此刻已经守住了什么。代价是自定义段住在 `config.json` 里、在仓库外，**任何测试都够不着它**——改坏了只有使用者自己知道。
