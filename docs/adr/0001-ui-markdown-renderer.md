# 界面 Markdown 渲染：自研窄覆盖渲染器，不引入解析器

index.html 的单页界面要把 Markdown 文档渲染成 DOM（技能介绍文档弹窗先有，规格卡片轻渲染与规格阅读弹窗后加）。决定：继续扩展页面内自研的 `renderMarkdown`——行内容全部经 `textContent` 组装、只覆盖文档实际用到的语法——而不是把 marked / markdown-it 一类成熟解析器的单文件拷进仓库。动因是两条既有纪律：仓库承诺零 npm 依赖、整体自包含；「行内容不走 innerHTML」是页面对任意 `.scratch/` 内容的安全底线，成熟解析器输出 HTML 字符串，两条都得破。

语法覆盖按实测收敛：对 4 个项目 19 篇 spec.md 的普查显示，现有渲染器之外只有表格、围栏代码块、斜体三种缺口（链接/图片 0 使用），扩展约几十行。未知语法一律降级为纯文本段落：不破页、无法注入脚本。日后真遇到覆盖不了的场景，先回看本 ADR 再决定是否升级为直接消费 lib/parse.mjs 的结构化结果渲染——那是重做安全 DOM 纪律的决策，不是顺手换库。
